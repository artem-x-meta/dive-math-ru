Натуральных чисел бесконечно много, поэтому утверждение «для любого $n$» нельзя доказать перебором. Единственный выход — **индукция**: показать утверждение для нуля и показать, что оно переживает переход к следующему числу.

В Lean у этого приёма есть приятная особенность: он выглядит ровно так же, как определение функции. Это не аналогия, а одно и то же.

## Рекурсивное определение

Сумму чисел от 1 до $n$ нельзя записать одной формулой, не доказав эту формулу. Зато можно определить рекурсивно: сумма до нуля равна нулю, а сумма до $n+1$ — это $(n+1)$ плюс сумма до $n$.

## Индукция: те же база и шаг

Теперь докажем формулу. Тактика `induction` разбивает цель на две — ровно те же, что были в определении.

<LeanSnippet file="DiveLean/Ch06/Induction.lean" region="induction-shape" title="Формула суммы" />

Разберём по частям.

- `| zero => rfl` — база. При $n = 0$ обе стороны считаются в ноль, и вычисления достаточно.
- `| succ k ih =>` — шаг. Здесь `k` — предыдущее число, а **`ih` — гипотеза индукции**, то есть утверждение, уже доказанное для `k`.
- `change` переписывает цель в развёрнутом виде: `sumTo (k+1)` по определению есть `(k+1) + sumTo k`.
- Дальше обычный `calc`, и в среднем шаге в дело идёт `ih`.

<Concept type="idea" title="Почему гипотеза индукции — это не жульничество">
  На первый взгляд странно: мы доказываем утверждение, пользуясь этим же утверждением. Но пользуемся мы им **для меньшего числа**, а оно к этому моменту уже обосновано — базой или предыдущим шагом. Ровно так же работает рекурсивная функция: она вызывает себя, но на меньшем аргументе, поэтому вычисление заканчивается. Индукция и рекурсия — одна конструкция, записанная с двух сторон.
</Concept>

## Ещё одна рекурсия

Определим удвоение $n$ раз — то есть $2^n$, но записанное рекурсивно:

И докажем, что показательный рост обгоняет линейный. Обрати внимание: шаг закрывается решателем `omega`, потому что после разворачивания определения задача становится линейной — гипотеза индукции работает как обычное неравенство в контексте.

<LeanSnippet file="DiveLean/Ch06/Induction.lean" region="power-grows" title="Удвоение растёт быстрее счёта" />

<Concept type="mistake" title="Где чаще всего застревают">
  Две типичные беды. **Первая:** забыть развернуть определение и удивляться, что `ring` не видит связи между `sumTo (k+1)` и `sumTo k` — их надо предъявить через `change` или `simp`. **Вторая:** доказать шаг, ни разу не использовав `ih`. Если гипотеза индукции не понадобилась, скорее всего, индукция вообще была не нужна — или доказано не то, что требовалось.
</Concept>

## Практика

1. Определи `double : Nat → Nat` рекурсивно и докажи `double n = 2 * n`.
2. Докажи `theorem sum_odd_is_square (n : Nat) : sumOdd n = n * n` самостоятельно, не подглядывая.
3. Докажи индукцией `theorem add_zero_right (n : Nat) : n + 0 = n`. Почему тут индукция может не понадобиться?
4. Докажи `theorem doubled_pos (n : Nat) : 0 < doubled n`.
5. Определи факториал рекурсивно и докажи, что он всегда положителен.
6. Попробуй доказать индукцией `∀ n : Nat, n < 100`. На каком шаге застрянешь и почему это правильно?

<details>
  <summary>Ответы и пояснения</summary>

  1. `def double : Nat → Nat | 0 => 0 | n + 1 => 2 + double n`, дальше индукция: база `rfl`, шаг `by change 2 + double k = 2 * (k + 1); rw [ih]; ring`.
  2. Смотри код выше — база `rfl`, шаг через `rw [ih]` и `ring`.
  3. Индукция сработает, но не нужна: в Lean `n + 0` сводится к `n` вычислением, поэтому хватает `rfl`. А вот `0 + n = n` уже требует индукции — сложение определено рекурсией по второму аргументу.
  4. `by induction n with | zero => decide | succ k ih => change 0 < 2 * doubled k; omega`.
  5. `def fact : Nat → Nat | 0 => 1 | n + 1 => (n + 1) * fact n`, затем индукция с `omega` или `Nat.mul_pos` в шаге.
  6. База пройдёт: $0 < 100$. А шаг — нет: из $k < 100$ никак не следует $k + 1 < 100$, и при $k = 99$ это прямо ложно. Так и должно быть, утверждение неверно. Полезный вывод: **шаг индукции обязан работать для всех $k$**, а не только для маленьких.

</details>

## Итог

- Рекурсивное определение задаётся базой и шагом; значения после этого вычисляются сами.
- `induction n with | zero => ... | succ k ih => ...` даёт ровно две цели той же формы.
- `ih` — уже доказанное утверждение для предыдущего числа; если оно не понадобилось, индукция, скорее всего, лишняя.
- Определение под рекурсией надо разворачивать явно, иначе тактики не увидят связи между соседними значениями.
- Рекурсия и индукция — одна конструкция: обе опираются на то, что аргумент уменьшается.

Дальше — неравенства: решатели, которые умеют то, чего не умеет `omega`, включая квадраты.
